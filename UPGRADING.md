# Upgrading Charming

This guide covers breaking changes on the road to 1.0, newest first. Each entry
shows before/after code for an app generated by an older version.

## Unreleased

### Component event handlers are declared explicitly

Component results (`[:submitted, value]`, `[:selected, value]`, `:cancelled`)
used to find a controller hook by naming convention. Declare the handler with
the `on_*` class DSL instead:

Before:

```ruby
class SearchController < ApplicationController
  def query_submitted(value)
    # ...
  end
end
```

After:

```ruby
class SearchController < ApplicationController
  on_submit :query, :run_search

  def run_search(value)
    # ...
  end
end
```

The declarations are `on_submit`, `on_select`, and `on_cancel`. Actions for
`on_submit`/`on_select` receive the value; `on_cancel` actions receive no
arguments.

The old convention still works but emits a one-time deprecation warning naming
the declaration to add. A component result with no handler at all — the old
silent-fallback case — raises `Charming::UnhandledComponentEvent` in
development and test (this catches typos in hook names), and logs a warning in
production before falling back to the default render.

### Routes are named screens, not URL paths

`config/routes.rb` registers each screen under a Symbol name. `root` is
unchanged and registers the reserved `:root` screen.

Before:

```ruby
MyApp::Application.routes do
  root "entries#show", title: "Entries"
  screen "/compose", to: "compose#show", title: "Compose"
  screen "/entries/:id", to: "reader#show", title: "Entry"
end
```

After:

```ruby
MyApp::Application.routes do
  root "entries#show", title: "Entries"
  screen :compose, "compose#show", title: "Compose"
  screen :entry, "reader#show", title: "Entry"
end
```

Dynamic segments (`:id`) are gone. Register one named screen per parametric
page and pass the values when you navigate.

### `navigate` replaces `navigate_to`, and takes a name plus params

Before:

```ruby
def entries_selected(entry)
  navigate_to "/entries/#{entry.id}"
end
```

After:

```ruby
def entries_selected(entry)
  navigate :entry, id: entry.id
end
```

Params arrive with their Ruby values intact — `params[:id]` is whatever you
passed (an Integer id, a record, anything). There is no URL decoding and no
string conversion.

`navigate :root` replaces `navigate_to "/"`.

Code that still passes a string path raises `ArgumentError` with a migration
hint. `Router#resolve(:typo)` raises `KeyError` listing the registered names.

### Sidebar filtering by route

The `Route` struct's `path` member is now `name` (a Symbol). If you filter
`sidebar_routes`, match on names:

Before:

```ruby
def sidebar_routes
  application.routes.all.reject { |route| route.path.include?(":") }
end
```

After:

```ruby
def sidebar_routes
  application.routes.all.reject { |route| %i[entry edit_entry].include?(route.name) }
end
```
